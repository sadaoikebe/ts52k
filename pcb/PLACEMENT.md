# RP2040版 基板レイアウトガイド

`rp2040` ブランチの基板（`ts52k.kicad_pcb`）で、RP2040 とその周辺部品をどこに置き、どう配線するかの指針です。

**現行の発注前情報:** [JLCPCB向け出力](jlcpcb/README.md)を参照してください。2026-10-28にFlashをMCU近傍へ移し、右側のマトリックス束を0.40 mmピッチに整理しました。U4は (35.4, 60.0) mm、180°、MCUとの中心間距離は11.45 mmです。上押し式SW1（C318884、47.6, 76.2 mm）と外周クリアランス0.25 mmを維持しています。下記の旧座標・検討メモは履歴です。

ATmega32U4 版のレイアウトを土台に、MCU まわりだけを置き換える方針で進めています。USBコネクタまわりとキーマトリクスの配線は原則そのまま残します。

## 前提

- MCU側の部品はすべて **B.Cu（裏面）** に置きます。表面のキースイッチの貫通端子・位置決め部は裏面にも出るため、部品外形との干渉確認が必要です
- SMD部品を片面に集約すると、JLCPCB の PCBA が片面実装で済みます。**F.Cu に部品を置かない**でください
- KiCad の座標系は **y が下向き**です。以下「北」＝ y が小さい方 ＝ 画面上、を指します
- USBコネクタ **J1 は (23.82, 43.59)**、基板の北端にあります
- 旧 ATmega32U4（U1）は **(23.8, 64.0)** にありました。マトリクスの配線はここへ向かって収束しています

---

## RP2040 の向き

**B.Cu / rot 180** で確定です。USB を北（J1側）に向ける以上、回転はこれで一意に決まります。

QFN-56 のダイ上の各辺が、基板上でどちらを向くか:

| 基板の向き | パッド | 中身 |
| :--- | :--- | :--- |
| **北**（J1側） | 43–56 | ADC_AVDD, VREG_VIN, VREG_VOUT, **USB_DM/DP**, USB_VDD, IOVDD, DVDD, **QSPI ×6** |
| **東** | 1–14 | IOVDD, GPIO0–11 |
| **南** | 15–28 | GPIO12–17, TESTEN, **XIN**, XOUT, IOVDD, DVDD, **SWCLK/SWDIO/RUN** |
| **西** | 29–42 | GPIO18–29, IOVDD — **全ピン未使用** |

ダイ上の呼び方と基板上の向きが入れ替わるのは、B.Cu に置いて裏返しているためです。パッド番号は基板を表から見ると時計回りに並びます。

ここから読み取れる重要な帰結:

- **USB と QSPI はどちらも北辺**。北辺を西から見ると ADC_AVDD → VREG → **USB** → IOVDD/DVDD → **QSPI** の順なので、**USBは北西へ、フラッシュは北東へ**分けて逃がします
- **西辺には信号が1本もありません。** +3V3 の引き込みと西側パスコンを、配線の混雑を気にせず置けます
- 南辺は SWD/XIN/RUN に半分を占有されています。マトリクス用に使えるのは GPIO12–15（東寄り4本）と GPIO16–17（西寄り2本）に分断されています

## GPIO割り当て（確定）

古いATmegaの配線が残した末端（スタブ）の並び順に合わせてあります。MCU跡地を中心に反時計回りで見ると、スタブの順序とパッドの順序が完全に一致し、**マトリクス同士の交差はゼロ**です。

### 南辺（西 → 東）

```
 P28   P27  │ P26  P25   P24   P23  P22   P21  P20  P19 │ P18  P17  P16  P15
 col1  row5 │ RUN SWDIO SWCLK DVDD IOVDD XOUT XIN TESTEN│ row4 row3 col6 col5

既存スタブの x座標（すべて y = 67.38）:
21.79 22.29                                              22.79 23.29 23.79 24.29
```

`col1` が GPIO15 ではなく GPIO17 なのはこのためです。南辺のマトリクス用ピンは SWD/XIN ブロックで 2本 + 4本 に分断されており、西端のスタブ2本（`col1`, `row5`）を西側の2本に割り当てると全体が単調な順序になります。

### 東辺（北 → 南）

```
 P1    P2   P3   P4   P5   P6   P7〜P12  P13  P14
IOVDD rpg1 rpg2 row1 row2 col3   未使用  col2 col4

既存スタブの y座標（すべて x = 27.13）:
      64.54 65.04 65.54 66.04 66.54
```

`col2` / `col4` のスタブは南辺（y = 67.38、x = 25.29 / 24.79）にあり、**南東の角を回り込んで**東辺の P13 / P14 に入ります。順序は保たれています。

## 配線ルール（配置の前に決めておく）

現在の設定は ATmega 版から引き継いだままで、**このままでは RP2040 のファンアウトができません。**

| 項目 | 現在値 |
| :--- | :--- |
| ネットクラス Default / Power | トラック 0.25mm、クリアランス 0.2mm、ビア φ0.8 / ドリル0.4 |
| 最小トラック幅 | 0.2mm |
| 最小ビア | φ0.4 / ドリル0.3 |

RP2040 のパッドは **幅 0.1786mm、ピッチ 0.4mm**（隙間 0.22mm）です。1辺に14本が並び、それぞれ真っ直ぐ外へ逃がすことになります。

- **トラック 0.25mm + クリアランス 0.2mm = 0.45mm ピッチ** → 0.4mm ピッチのパッドから出られません
- **トラック 0.2mm + クリアランス 0.2mm = 0.4mm ちょうど** → ぎりぎり通ります
- 余裕を見るなら **トラック 0.15mm / クリアランス 0.15mm**

対応:

1. `Board Setup → Design Rules → Net Classes` に **MCUファンアウト用のトラック幅（0.15〜0.2mm）を追加**するか、`Pre-defined track widths` に登録して手動で切り替える
2. ビアも φ0.8 では大きすぎます。MCU近傍用に **φ0.5 / ドリル0.3** 程度を追加
3. **JLCPCB の2層標準プロセス**は概ね トラック/クリアランス 0.127mm(5mil)、ドリル 0.3mm まで。0.15/0.15/φ0.5 は標準の範囲内ですが、発注前に JLCPCB の最新の製造能力ページで確認してください

パッドリングから離れたら通常の 0.25mm に戻して構いません。電源（+3V3 / 1V1 / GND）は可能な範囲で太く。

## 部品ごとの配置ガイド

距離の要求が厳しい順に並べてあります。スペースが足りなくなったら、上から順に守って下から譲ってください。

### ★★★ 妥協できない

#### C8 / C9 / C10（1µF, 1V1）— 2mm以内

RP2040 のコア電源です。内蔵レギュレータの出力 `VREG_VOUT`(P45) から `DVDD`(P50, P23) へ戻る経路にあり、コアのスイッチング電流がすべてここを通ります。

- P45 と P50 は北辺で隣同士 → 北辺に2個
- P23 は南辺 → 南辺に1個
- 各コンデンサの GND パッドの**真横にビア**を落とし、GNDベタへ最短で落とす
- **1V1 は独立した小さな島**として引く。長い配線で引き回さない

#### R9 – R13（22Ω, QSPI）— 3mm以内

ソース終端なので、**ドライバ側 = RP2040 側**に置くことに意味があります。フラッシュ側に置くと効果がありません。

北辺の P51〜P55 に密着させて並べ、その先にフラッシュを置きます。Raspberry Pi Pico と同じ構成です。

### ★★ 近い方がよい

#### C6 / C11 – C18（1µF, +3V3, 9個）— 3mm、最悪5mm

内訳は IOVDD ×6（P1, P10 東 / P22 南 / P33, P42 西 / P49 北）、ADC_AVDD（P43 北）、USB_VDD（P48 北）、そして **X2 の電源用に1個**です。

優先度:

1. **P49**（北・DVDD と USB_VDD の隣）、**P22**（南・DVDD P23 の隣） — コアの直近なので効きます
2. **P48 USB_VDD** — USBトランシーバの電源
3. **X2 の VDD（P4）の真横** — 後述
4. P1, P10（東） — マトリクス配線と場所を取り合うので、ここは配線を優先して2〜3mm離してもよい
5. **P33, P42（西）— 一番楽**。西辺は信号ゼロなので自由に置けます
6. **P43 ADC_AVDD — 一番どうでもよい**。ADCを1本も使っていないので、最後に余った場所へ

#### R7 / R8（22Ω, USB）— 5mm以内

P46/P47 の真横に置き、そこから D+/D- をペアのまま北へ、U2 経由で J1 まで約20mm。

- 2本を並走させ、間隔を一定に、長さを 1mm 以内で揃える
- **途中でビアを打たない**（両方とも B.Cu で完結させる）
- 2層 1.6mm 基板で 90Ω 差動インピーダンスは物理的に成立しませんが、USB Full-Speed (12Mbps) なら実用上問題ありません

#### U4 W25Q128JVS（フラッシュ）— 北辺から15mm以内

QSPI の総配線長は 25〜30mm 以内が目安（Pico は約8mm）。**北東**（例: x 30〜38, y 58〜62）に置くと、北西へ抜ける USB 配線と場所を取り合いません。

`R2`（10kΩ, `QSPI_SS_N` プルアップ）も U5-P56 / U4-1番ピンの近くへ。

#### C7（1µF）/ R4（10kΩ）— RUN(P26) から10mm以内

電源投入時のリセット遅延を作る RC です。静的な信号なので厳密ではありませんが、C7 は RUN ピンの近くに置きます。

### ★ 遠くてよい

#### X2 ASE-12MHz（発振器）— 25mmまで可

**足は実質1本**（P3 OUT → `XIN`, P20）です。水晶振動子ではなく**発振器モジュール**なので、発振回路が内部で完結しており、出力は CMOS ドライブの低インピーダンスです。水晶の XIN/XOUT ペアのような「1mmでも短く」という制約はありません。

代わりに守ること:

- **P4（VDD, +3V3）の真横にパスコンを1個**置く。発振器は自分の電源が汚れると位相ノイズが出ます
- `R3`（10kΩ, EN プルアップ）は P1 の近くへ
- 12MHz の矩形波なので、**USBペアと長距離並走させない**。マトリクスの行線と長く平行に走らせない
- 置き場所の候補: U5 の南、x 20〜30 / y 68〜70

#### U3 XC6206P332MR-G（LDO）— J1 と U5 の間ならどこでも

J1 から +5V を受けて +3V3 を U5 へ渡すので、両方が短くなる位置に。y 51〜53 の隙間か、U2 の南あたり。

- 入力側 `C3`(4.7µF) / `C4`(1µF) を VI(P3) の横に
- 出力側 `C5`(4.7µF) / `C2` / `C21`(各1µF) のうち **1個は U5 側に置いてバルクコンデンサとして使う**と一石二鳥
- GND は P1、VO は P2。EN は無い

#### R14（1kΩ）+ SW1（BOOTSEL）— R14 の位置だけ重要

**R14 は `QSPI_SS_N` ライン上、U5 / U4 のすぐ近くに置いてください。** スイッチまでの長い配線は R14 の先に垂らします。

こうすると `SS_N` ラインから見えるのは 1kΩ だけになり、スイッチまでの長い線が QSPI にスタブ（アンテナ）としてぶら下がりません。逆にすると起動時のフラッシュ読み出しが不安定になり得ます。Pico も同じ構成です。

**SW1 本体の位置は自由です。** ケースの押下穴の位置に合わせて決めてください。

#### J2 Tag-Connect TC2030-IDC-NL — 完全に自由

SWD は数MHz なので配線長は問題になりません。制約は物理的なものだけです:

- NL版は位置決めの脚がないため、**3つのアライメント穴**が必要
- プローブ本体（φ約9mm）が降りてくるので、**周囲に背の高い部品を置かない**
- ケーブルが逃げられるよう**基板の端寄り**に
- ケースを開けずに刺せるようにするかは、ケース設計と併せて判断

### 触らない部品

| 部品 | 現在位置 | 理由 |
| :--- | :--- | :--- |
| J1（USB-C） | (23.82, 43.59) | 基板の北端。ケースの開口位置が決まっている |

## 作業順序

### 配置

1. **U5** を (23.8, 64) 付近、**rot 180 / B.Cu** で配置
   - RP2040 は ATmega よりずっと小さいため、既存スタブの端（南 y = 67.38、東 x = 27.13）が **ちょうどパッドリング（中心から3.40mm）の上**に来ます。ファンアウトの余地を作るために、**U5 を1〜2mm北西にずらすか、各スタブの先端2〜3mmを削る**ことになります
2. **1V1 のパスコン** C8 / C9 / C10
3. **QSPIブロック** — R9–R13 → U4 → R2 を北東へ
4. **USB** — R7 / R8 を北西へ、J1 まで
5. **+3V3 のパスコン**を優先度順に埋める
6. **X2 + R3 + 専用パスコン**を南へ
7. **U3 + 入出力コンデンサ**を J1 と U5 の間へ
8. **C7 / R4**（RUN）、**R14**（SS_N 上）
9. **J2**、**SW1**（ケースと相談）

### 配線

制約の強い順に引くと手戻りが減ります。

10. **EPAD (P57) に GND サーマルビアを4〜9本**
11. **USB差動ペア**（R7/R8 → U2 → J1）— ビアなし、B.Cu 完結、等長
12. **QSPI 6本** — 22Ω → U4
13. **1V1 の島**と各パスコンの GND ビア
14. **+3V3** — 西辺から引き込んで各 IOVDD へ。細い線で引き回さず、面か太い線で
15. **XIN**、**SWD/RUN**
16. **マトリクス11本** — 既存スタブの先端とファンアウトを繋ぐだけ
17. DRC → シルクの整理 → 「仕上げ」へ

## やってはいけないこと

### Cleanup Tracks & Vias の "Delete dangling tracks"

**実行しないでください。** MCU 近傍に意図的に残してある26本のマトリクス末端が、連鎖的に削られます。KiCad のこの機能は、宙に浮いた端から次のパッドまで1セグメントずつ剥がしていくため、行線・列線が根元まで消えます。

ATmega時代のゴミ銅箔（ネット名を失った `(net "")` のトラック）は既に削除済みなので、この機能で掃除するものは残っていません。

### Update Symbols from Library の一括実行

KiCad 標準ライブラリ側で `Memory_Flash:W25Q128JVS` のピン位置が変更されているため、U4 が全ネットから外れます。詳細は README の「開発環境」を参照。

### Update PCB from Schematic の "Link footprints using reference designators"

**オフのままにしてください。** 旧 SW1（リセットスイッチ）↔ 新 SW1（BOOTSEL）、旧 J2（ピンヘッダ）↔ 新 J2（Tag-Connect）が誤って対応付けられます。

### ダイオードのフットプリントをライブラリから更新

`lib_footprint_mismatch` が53件出ますが、**基板側が正**です。`main` ブランチで実際に製造・実装できている版なので、KiCad標準ライブラリの新しい定義に揃える必要はありません。

## ツール

### `clear_copper_under_parts.py`

部品配置が固まったあと、**選んだフットプリントの下に食い込んでいる B.Cu トラックを切り詰め、直下のビアを消す**スクリプトです。マトリクス末端のスタブは部品の外に残るようクリップします（全体の dangling 削除はしません）。

```sh
python clear_copper_under_parts.py --dry-run          # 差分の見積もりだけ
python clear_copper_under_parts.py                    # デフォルトは RP2040 側 35 部品
python clear_copper_under_parts.py --refs U5,U4,C8,C9  # 配置が変わったら refs を明示
```

配置が動いている途中では使わないでください。部品を動かしたあとに、最終位置で一度だけ回す想定です。

### `_place_mcu.py`

MCU 側 35 部品の粗配置座標です。初期配置用。位置を直したらこの辞書か、`--refs` 側を更新してください。

## 検証のしかた

GUI を開かずに状態を確認できます。作業の区切りごとに回すと事故に早く気づけます。

```sh
kicad-cli sch erc                              -o erc.rpt  ts52k.kicad_sch
kicad-cli sch export netlist                   -o net.net  ts52k.kicad_sch
kicad-cli pcb drc --schematic-parity --refill-zones -o drc.rpt ts52k.kicad_pcb
```

- **`schematic parity 0`** が、回路図と基板が一致していることの担保です。回路図を触ったら必ず `Update PCB from Schematic` を実行して 0 に戻します
- ネットリストを配線変更の前後で比較し、**各ネットのノード集合が変わっていないこと**を確認すると、意図しない接続変更を確実に検出できます

## 仕上げ（ガーバー出力の前に）

1. 必要な設計変更があれば反映する。ティアドロップ追加などの形状変更は、一括適用する前にクリアランスと製造上の必要性を確認する
2. **ゾーンを塗り直す** — `Edit → Fill All Zones`（**B** キー）
   - レイアウト作業中はGNDベタを塗らないほうが快適です（部品を動かすたびの再計算がなく、git の差分も読める）
   - **塗り忘れたままガーバーを出すと、GNDベタのない基板が焼かれます**
3. **DRC を実行**して残った違反を潰す（シルク、`starved_thermal`、`via_dangling`、J1 の属性）
4. **出力** — [JLCPCB 向け出力手順](jlcpcb/README.md)に従ってガーバー + ドリル、BOM、実装座標を生成する
   - JLCPCB 実装は Bottom 単独。J1 は固定脚がスルーホールのため、座標出力に `--smd-only` を使うと抜けます
