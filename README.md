# TS52K

親指シフト（NICOLA配列）を前提に設計した、52キーの自作キーボードです。ハードウェア（回路・基板・ケース）一式をオープンソースで公開しています。

解説記事: [親指シフトキーボードを作った話](https://qiita.com/sadaoikebe/items/e3715383058286457a23)

## 特徴

- **親指シフト専用設計** — かな入力だけでなく、英数レイヤーも親指シフトで打てる配列
- **52キー + ロータリーエンコーダ** — 50%サイズに親指キーを確保したレイアウト
- **QMK対応** — ファームウェアはQMKベース
- **JLCPCBで発注できる基板** — PCBA（部品実装込み）を想定した設計
- **FDM 3Dプリンタで出力できるケース** — 特殊な設備なしで製作可能

## ブランチと開発状況

| ブランチ | MCU | 状態 |
| :--- | :--- | :--- |
| `main` | ATmega32U4 | **完成・製作実績あり** |
| `rp2040` | RP2040 | 回路図完成、**基板レイアウトは未着手** |

このドキュメントは `rp2040` ブランチの内容を説明しています。

`rp2040` ブランチは ATmega32U4 版からの設計変更版です。回路図・シンボル・フットプリントは完成しており ERC もクリーンです。基板（`pcb/ts52k.kicad_pcb`）は ATmega32U4 時代の銅箔を除去し、GPIO の割り当てまで済んでいますが、**部品配置と配線はこれから**です。実際に発注できる状態ではありません。

レイアウトの方針は [`pcb/PLACEMENT.md`](pcb/PLACEMENT.md) にまとめてあります。

ATmega32U4 版から変更した点:

- MCU を RP2040 に変更（外部QSPIフラッシュ 16MB を追加）
- 16MHz セラミックレジネータ → 12MHz 発振器モジュール
- ISPヘッダ → Tag-Connect（SWD）
- WS2812B RGB LED、ポリヒューズ、リセットスイッチを削除

## 回路の構成

```
USB-C (J1) ─┬─ VBUS 5V ─→ AP2112K (U3) ─→ 3.3V ─┬─→ RP2040 IOVDD
            │                                    ├─→ フラッシュ (U4)
            │                                    └─→ 発振器 (X2)
            │
            └─ D+/D- ──→ ESD保護 (U2) ─→ 27Ω ──→ RP2040 USB

発振器 (X2) ── 12MHz ──→ RP2040 XIN ──→ 内蔵PLL ──→ 133MHz / 48MHz(USB)

RP2040 ─ QSPI (27Ω×5) ──→ W25Q128JVS (U4)   起動時にここからコードを読む
       │                    └─ CS ─ 10kΩ↑3V3、1kΩ ─ SW1 ─ GND（BOOTSEL）
       ─ GPIO ×11 ──────→ キーマトリクス
       ─ GPIO ×2 ───────→ ロータリーエンコーダ A/B相
       ─ SWD ───────────→ Tag-Connect (J2)
```

Raspberry Pi Pico のリファレンス設計をおおむね踏襲しつつ、キーボード向けに変更を加えた構成です。

### J1 — USB-Cレセプタクル（HRO TYPE-C-31-M-12）

USB 2.0 専用の16ピン品です。フル24ピンのType-Cから USB 3.x 用の高速差動ペアを省いたもので、キーボードに 3.0 の帯域は不要なため、安価で実装しやすいこれを使っています。

Type-C は裏返して挿してもピン配置が上下反転するだけで使えます。これに対応するため、`D+` を A6/B6 の両方に、`D-` を A7/B7 の両方に接続しています。`VBUS` と `GND` も複数ピンを束ねて電流容量を確保しています。

`CC1`/`CC2` はそれぞれ **5.1kΩ で GND** に落としています。ホストはこの抵抗値を見て「相手はデバイス側」と判定し、VBUS に 5V を供給します。**この抵抗がないと電源が入りません。**

`SBU1`/`SBU2`（オーディオ・DisplayPort 用の予備線）とシェルドは未接続です。

### U2 — TPD4E1U06（ESD保護アレイ）

USB の D+/D- に入る静電気を、RP2040 に届く前に電源かGNDへ逃がします。キーボードは人が常時触れる機器なので、この保護は実質必須です。

型番の "U" は**超低容量**（約0.5pF）を意味します。保護素子は信号線に寄生容量としてぶら下がるため、容量が大きいと USB の波形が鈍ります。汎用のESDアレイでは通信が不安定になるため、USB用には低容量品を選ぶ必要があります。

4チャンネル品ですが、この基板では2チャンネル（D+/D-）のみ使用しています。

### U3 — AP2112K-3.3（LDOレギュレータ）

USB の 5V を 3.3V に変換します。出力 600mA に対し実消費は数十mA程度で、余裕があります。

`EN` を `VIN` に直結しているため、USB が挿さっていれば常に ON です。キーボードに電源制御は不要なのでこれで十分です。Raspberry Pi Pico と同じ品種です。

### U5 — RP2040（MCU）

デュアルコア Arm Cortex-M0+、133MHz、QFN-56（7×7mm）。

**電源系統が特徴的です。** RP2040 は内部に 1.1V のスイッチングレギュレータを内蔵しており、`VREG_VIN`(44) に 3.3V を入れて `VREG_VOUT`(45) から出た 1.1V を、`DVDD`(23, 50) で自分に戻して入れるという構成をとります。基板側では 1V1 ネットにパスコンを置くだけです。

```
+3V3 ──→ VREG_VIN (44) ──→ [内蔵1.1Vレギュレータ] ──→ VREG_VOUT (45)
                                                            │
                                                          1V1ネット
                                                            │
                                                      DVDD (23, 50)
```

| ピン | 接続 | 用途 |
| :--- | :--- | :--- |
| IOVDD ×6 | +3V3 | IOバッファ電源 |
| ADC_AVDD | +3V3 | ADCアナログ電源 |
| USB_VDD | +3V3 | USBトランシーバ電源 |
| **VREG_VIN** | **+3V3** | **内蔵レギュレータ入力** |
| VREG_VOUT | 1V1 | 内蔵レギュレータ出力 |
| DVDD ×2 | 1V1 | コア電源入力 |
| TESTEN | GND | 製造テスト用。データシート通り接地 |
| EPAD | GND | QFN裏面サーマルパッド |

`RUN`(26) は 10kΩ で 3.3V にプルアップし、コンデンサで電源投入時のリセット遅延を作っています。Tag-Connect の RESET から引き下げることもできます。

### X2 — ASE-12MHz（発振器モジュール）

RP2040 の標準構成は「水晶振動子 + 負荷容量2個」ですが、この基板は**発振回路を内蔵した完成品モジュール**を使っています。部品点数が減り、負荷容量の調整も不要になる代わりに、コストは水晶より高くなります。

`XOUT`(21) を未接続にしているのがこの構成の目印です。外部から完成したクロックを注入する場合、`XIN` だけを駆動し `XOUT` は開放にするのが正しい使い方です。

`EN` は 10kΩ で 3.3V にプルアップして常時イネーブルにしています。

12MHz は RP2040 の要求仕様で、内蔵PLLがここから 133MHz のシステムクロックと 48MHz の USB クロックを生成します。USB は周波数精度に厳しいため、ここは妥協できません。

### U4 — W25Q128JVS（QSPIフラッシュ）

128Mビット = **16MB** のシリアルフラッシュ。

**RP2040 にはプログラム用の内蔵フラッシュがありません。** 起動時にこのチップからコードを読み出して実行（XIP）するため、これが無いと何も動きません。

データ線4本を並列に使う Quad SPI で接続し、各線に 27Ω の直列抵抗を入れてリンギングと EMI を抑えています（Raspberry Pi Pico には無い追加です）。`/CS` は 10kΩ でプルアップし、電源投入直後にフラッシュが誤ってコマンドを受け取らないようにしています。

16MB は QMK には十分すぎる容量ですが（Pico は 2MB）、価格差が小さいため余裕を取っています。

### J2 — Tag-Connect TC2030-IDC-NL（書き込み・デバッグ端子）

SWD 接続用のフットプリントです。**コネクタ部品は実装しません。** 基板上はランドと位置決め穴だけで、専用のポゴピンケーブルを押し当てて接続します。

"NL" は **No Legs** の意味で、基板を貫通する固定爪用の穴が不要なタイプです。押さえている間だけ導通するので、書き込み時は手で保持するか治具を使います。

完成品にピンヘッダが飛び出さず、ケースに穴も不要なため、外観と厚みを損ないません。

### キーマトリクス

`col1`〜`col6` と `row1`〜`row5` の計 **11本のGPIO** で、52個のキースイッチとロータリーエンコーダの押し込みスイッチ、合計53接点を読み取ります。

単純な 6×5 マトリクスでは30接点しか読めないため、ダイオードの向きを使い分けて容量を倍にする **duplex マトリクス**構成をとっています。各接点にダイオードを入れることで、同時押し時のゴースト（誤検出）を防いでいます。

### SW1 — BOOTSEL ボタン

RP2040 は起動時に `QSPI_SS` が Low だと USB マスストレージのブートローダに入り、UF2 ファイルをドラッグ&ドロップで書き込めるようになります。SW1 はそのためのボタンで、`QSPI_SS_N` を **1kΩ(R14) 経由で GND** に落とします。

抵抗を挟むのは Raspberry Pi Pico と同じ理由です。

- 通常動作中は RP2040 が CS を High に駆動しているため、抵抗なしでボタンを押すと 3.3V を直接 GND に短絡してしまう
- 10kΩ(R2) のプルアップとの分圧で 3.3V × 1/11 ≒ 0.3V となり、確実に Low と判定される

書き込み手段は2通りあります。

| 方法 | 手順 |
| :--- | :--- |
| UF2（SW1） | SW1 を押しながら USB 接続 → ストレージとして認識 → UF2 をコピー |
| SWD（J2） | Tag-Connect ケーブルを当てて書き込み。デバッグもこちら |

## 開発環境

- **KiCad 10.0** 以降

回路図を編集する場合、以下の点にご注意ください。

**`Tools → Update Symbols from Library` は慎重に実行してください。** KiCad 標準ライブラリ側で `Memory_Flash:W25Q128JVS` と `Regulator_Linear:AP2112K-3.3` のピン位置が変更されているため、そのまま更新すると U3・U4 が全ネットから外れます。この2つは意図的に古いキャッシュ定義のまま維持しています。

また、フィールド関連のオプション（`Update/reset field text` など）を有効にすると、電源シンボルの Value が書き換わってネット名が変わる可能性があります。

**`Tools → Update PCB from Schematic` では `Link footprints using reference designators` をオフのままにしてください。** フットプリントは通常 Unique ID でシンボルと紐付いており、参照名での紐付けに切り替えると、ATmega32U4 版と RP2040 版で同じ参照名を持つ別部品（旧 SW1 リセットスイッチ ↔ 新 SW1 BOOTSEL、旧 J2 ピンヘッダ ↔ 新 J2 Tag-Connect）が誤って対応付けられます。
