# TS52K 静電容量版（EC版）— プロジェクトメモ

開始: 2026-11-12（Sadao の構想、サイドチャット「TS52K 静電容量版」）
位置づけ: TC69 の52キー版。土台は ts52k リポジトリの RP2040 版（有線・RP2040オンボード）。XIAO は貼らない。

## 構想
- TS52K（52キー親指シフト）の静電容量無接点（EC）版を作る
- 未決の基板構成（アナログ成立性の観点で判断）:
  1. 基板を広げる（一枚で収める）
  2. HHKB 式の子ボード（ドーターボード）
  3. 4層基板（アナログ的に意味がある場合のみ。それ以外なら採らない）

## ペース配分（Sadao の指示、厳守）
- 急がない。最優先ではない
- Fable は「本当に判断が要るアナログ設計の核心」だけ。用前に必ず check-usage-limits.py で枠確認
- 調査・洗い出し・整理は Astra/Sol/Terra 等の下位モデルで少しずつ
- 他プロジェクト（KOBE WARP、oyayubi-ime、TS52K wireless 等）の山場と競合させない

## 前提の訂正（2026-11-12、Sadao の指摘で確定）
- **ハード制約：基板外形は拡大しない。** TS52K は枠まで小さくシンプルなのがウリ。TC69 のようにキーのない所まで基板を広げる案は採らない
- 広い静電容量パッド自体がコンデンサを形成している。問題は部品点数の置き場ではなく、**狭い基板の上でアナログの健全性を保つこと**（寄生容量、ノイズ、GND、デジタル配線との結合）。アナログ設計がこのプロジェクトの核心で、ここがボロボロだとどうしようもない
- 選択肢の意味はこの制約の下で読み替える：子ボード＝アナログ部・MCU をパッド基板から分離する手段（HHKB式）／4層＝パッド下に専用 GND プレーンを確保するアナログ的手段。どちらも「枠を広げずにアナログを成立させる」ための案
- **RP2040 の十分性は論点から外す**：TC69 が RP2040 で快調だったという本人の実績で決着（10-bit ADC でも良好だった）。「RP2040で足りるか」を調査対象にしない
- 核心のアナログ設計は **Fable 5.2 に全振り**（Sadao の裁定）。投入は枠と他プロジェクトの山場を見て行う

## 当面の方針
いきなり基板設計に入らず、実現性調査から：
- 先行OSS EC基板（TC69 その他）のセンス方式：AFE構成、マルチプレクス方式、RP2040 の ADC／デジタル閾値で足りるか
- 52キー分の電極レイアウトと既存フォームファクタの両立性
- 3案（広げる／子ボード／4層）の比較材料づくり
