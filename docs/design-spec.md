## 2. 回路仕様

TC69 の回路（報告書 §2.1、`ref/out/tc69.net`）からの差分で定義する。ネット名は TC69 のスケッチではなく**回路図側**に合わせる（`SENSE`＝高インピーダンスの節点、`ADC`＝オペアンプ出力）。

### 2.1 ネット表

| ネット | つながるもの |
|---|---|
| `ROW1`〜`ROW4` | RP2040 GPIO18〜21 → 直列 100 Ω（R_ROW1〜4、MCU 側）→ L4 → ビア → L1 の行バス → その行の全キーの駆動側電極 |
| `COL1`〜`COL14` | その列のキーのセンス側電極（1 列に各行 1 個まで）、100 kΩ の対 GND（R_C1〜14、MUX の近く）、MUX の入力 1 本 |
| `SENSE` | MUX A の共通端子（ピン 3）、MUX B の共通端子、C2（対 GND）、C2B（未実装の席、対 GND）、R3 の片側、RP2040 GPIO26（PURGE）、テストポイント TP_SENSE |
| `AMP_IN` | R3 の反対側、オペアンプの＋入力 |
| `AMP_FB` | オペアンプの−入力、R1（対 AGND 点）、R2（出力から） |
| `ADC` | オペアンプ出力 → 0 Ω の席（R_ADC）→ RP2040 GPIO28（ADC2）、テストポイント TP_ADC |
| `S0` | GPIO22 → MUX A の INH（ピン 6）、74AHC1G04 の入力 |
| `S0_N` | 74AHC1G04 の出力 → MUX B の INH |
| `S1`／`S2`／`S3` | GPIO23／24／25 → MUX A・B 共通の A（ピン 11）／B（ピン 10）／C（ピン 9） |
| `+3V3A` | +3V3 から 22 Ω（R_F）を通った先。4.7 µF＋100 nF。オペアンプ、MUX × 2、1G04 の電源 |
| `ENC_A`／`ENC_B` | GPIO0／1（Rev 0.2 のまま） |
| `ENC_SW` | エンコーダの押しボタン → GPIO2（マトリクスから外す。内蔵プルアップ、反対側は GND） |
| `PLATE` | ランド付きの固定穴 1 個 → 0 Ω の席（未実装）→ GND |

- `S0`＝0 で MUX A、`S0`＝1 で MUX B が有効（TC69 と同じ論理。確認）。
- MUX の VEE（ピン 7）と VSS（ピン 8）は GND。使わない入力（MUX A の 2 本）は GND。
- CD4051B のピン番号（入力 X0〜X7 ＝ 13、14、15、12、1、5、2、4）は記憶値。シンボル作成時にデータシートで照合する。
- GPIO27 と GPIO29 は未接続のまま、ファームで LOW 出力に固定する（PURGE と ADC の隣を静かにする）。
- **列と MUX 入力の対応は配線の都合で自由に決めてよい**。ファームは表で持つ（§6.2）。

### 2.3 変えないこと

- PURGE は GPIO 直結（MOSFET を入れない）。
- `ecs_pad` の寸法と向き（全キー 0°、回転させない）。
- 100 kΩ の値。
- ADC_AVDD と IOVDD は +3V3 直結のまま（行の振幅と ADC の基準が同じ電源なので比で打ち消される）。`+3V3A` に移さない。

## 4. 配置

座標は Rev 0.2 の基板座標（mm、y は下向き）。

| 塊 | 位置 | 内容 |
|---|---|---|
| デジタル島 | x 16〜45、y 41〜82 | Rev 0.2 のまま。ただしフラッシュ U4 と QSPI は c2 の縦配線（MX7→MX8、x 33〜38）から 2 mm 以上離れるよう USB 側（北西）へ寄せる |
| AFE | (32, 89) 付近、半径 7.5 mm の空き地 | C2、C2B、R3、U_AMP、R1、R2、R_ADC、R_F、C_F1、C_F2、TP_SENSE、TP_ADC、TP_GND |
| MUX A | (75, 108) 付近（MX14 と MX23 の間、23 × 19 mm） | U_MUXA、R_C1〜6、100 nF |
| MUX B | (223, 103) 付近 | U_MUXB、R_C7〜14、100 nF。SOIC-16 は MX52・MX82・MX58 のリングの下にかかる（4層なので可） |
| U_INV | MUX A の脇 | S0 は静的な信号なので場所は問わない |
| R_ROW1〜4 | RP2040 のピン 29〜32 の出口 | 島の中 |

### 4.2 固定穴（提案、機構側の確認が要る）

EC は基板をプレートへねじで締める（TC69 は M2 × 12 本、プレートにタップ）。Rev 0.2 には固定穴が無いので新設する。TC69 と同じ流儀（Ø2.1 NPTH、行の中心線上、隣り合うキーの中間）で 12 個：

| 行 | 穴の位置 (x, y) |
|---|---|
| 行1 (y 54.77) | (61.91)、(119.06)、(176.21)、(233.32) |
| 行3 (y 92.87) | (57.15)、(133.35)、(209.55)、(284.0) |
| 行4 (y 111.92) | (19.05)、(122.6)、(200.03)、(280.99) |

- 行1 と行3 の穴は 1U どうしの中間で、TC69 と同じく穴の縁がリング外周に接する（中心から 9.53 mm）。(284.0, 92.87) は MX66 の右の空き地。行4 は幅広キーの間。
- 列の縦配線はパッド中心を通り、行バスは行間を通るので、行の中心線上の穴はどちらにも当たらない。下の帯（y 113.2 以下）にもかからない。
- デジタル島の中には置かない。(19.05, 111.92) は c1 の回収と SENSE の幹線に近いので、穴の縁から 1 mm 以上離して通す。
- うち 1 個（島に近い (19.05, 111.92) を推奨）をランド付きにして `PLATE` へつなぐ。
- **NiZ ハウジングの外形と TS52K のキー配置（段ずれ 0.25U／0.5U）での干渉は確認していない。** プレート設計と合わせて位置を確定する。穴は L2 に Ø3 mm 程度の逃げを作るだけで、遮蔽には影響しない。

## 5. 配線規則

報告書 §4.4 の規則を数値で固定する。KiCad では「HIZ」（COL*、SENSE、AMP_IN、AMP_FB）と「ASYNC」（USB、QSPI、XIN、SWD、ENC_*）のネットクラスを作り、カスタムルール（`.kicad_dru`）で検査する。

| # | 規則 | 値 |
|---|---|---|
| 1 | L2 に配線・スロット・分割を入れない | DRC：L2 に GND 以外の銅が無いこと |
| 2 | HIZ と、マトリクス以外の全ネットの間隔 | 2.0 mm 以上。間は GND ベタ |
| 3 | HIZ どうし（列と列、列と SENSE）の中心間 | 1.5 mm 以上。間は GND ベタ（線幅 0.2 mm なら隙間 1.3 mm、ベタが入る） |
| 4 | HIZ の線幅 | 0.2 mm（TC69 は 0.25 mm。4層では対 GND 容量を減らす側に寄せる） |
| 5 | HIZ の真上の L3 | GND のまま（島の外なので自動的に満たされる。c1・c2 が島を通る区間は L3 配線を置かない） |
| 6 | AGND 点 | C2、C2B、R1 の GND 側とオペアンプの V− を L4 の小さな銅島で結び、**ビア 1 か所**で L3／L2 へ落とす。ほかの GND 電流をこの島に通さない |
| 7 | SENSE 節点の銅 | C2・R3・PURGE 引き込みの分岐は AFE の中で最短に。R3 から＋入力までは 3 mm 以下 |
| 8 | L1 | 非同期信号を引かない。行バスは行間（リング間 2.05 mm の中央）を横に、線幅 0.25 mm |
| 9 | 行と列 | 行は横、列は縦、交差は直角。L4 の行引き込み（行間のビア → パッド中心ビア、約 8 mm）と列の縦配線は、中心ビアの間隔 2.38 mm より近づけない |
| 10 | ガードリング | 1 個につき 2 か所以上のビアで L2 へ |
| 11 | ASYNC | 島の中と上の帯だけ。島の外周に GND ビアの列（2 mm 間隔）を打ち、L2〜L4 をつなぐ |
| 12 | PURGE（GPIO26）と ADC（GPIO28）の引き込み | 島の中では隣を GND ガードではさむ。GPIO27 と 29 のパッドは配線を出さない |
| 13 | SENSE の幹線の長さ | 約 230 mm（推定）。これ以上延ばさない。枝を作らない（MUX A の共通端子を経由して MUX B へ一筆書き） |

**配置の時点で止めて確かめること**：c2 の縦配線と MX7・MX8 の中心ビアがフラッシュ・QSPI から 2 mm 取れているか。取れなければフラッシュをさらに寄せる。ここが唯一、Rev 0.2 の島をそのまま使えない箇所。

## 6. ファームウェア仕様

出発点は回収した `ref/qmk-capacitive/final/matrix.c`。置き場所は sadao-master の `keyboards/` の新しいキーボード定義（firmware-audit.md §4.3）。

### 6.1 ピン

| 信号 | GPIO | 設定 |
|---|---|---|
| ROW1〜4 | 18〜21 | 出力。待機中は LOW |
| S0〜S3 | 22〜25 | 出力 |
| PURGE | 26 | 待機中は出力禁止（Hi-Z）、プルなし、デジタル入力バッファ切 |
| ADC | 28（ADC2） | アナログ入力、プルなし、デジタル入力バッファ切 |
| 固定 LOW | 27、29 | 出力 LOW |
| ENC_A／B、ENC_SW | 0／1、2 | Rev 0.2 と同じ／入力プルアップ |

### 6.2 走査（守る順序）

```
for 列 c in 走査表:                 # 14 列
    S0〜S3 ← addr[c]                # 列が変わるときだけ
    for 行 r in rows_of[c]:         # その列にキーがある行だけ（合計 52 交点）
        PURGE を LOW 出力            # ① 必ずストローブの前
        t_purge 待つ
        PURGE を Hi-Z
        ─ 割り込み禁止 ─
        ROW[r] ← HIGH               # ②
        t_cap 待つ（固定）           # ③
        ADC 変換開始、完了待ち        # ④
        ROW[r] ← LOW                # ⑤
        ─ 割り込み許可 ─
```

- **①→②の順は成立条件**（報告書 §6-1）。列を切り替えた直後の交点にも必ず①が入る。高速化でも①を省かない、②の後ろへ動かさない。
- `addr[c]` と `rows_of[c]` は表にする。`addr` の bit0 が S0（MUX の選択）、bit1〜3 が MUX の入力番号。基板の配線で決まった対応をここに書く。
- 初期値：`t_purge`＝20 µs（QMK 最終版と同じ）、`t_cap`＝実機で決める（§8 M3。モデルではピークは行の立ち上がりから約 3.5 µs、推定）。
- ②〜④は RAM 上の関数にする（`__no_inline_not_in_flash_func`）。待ちは `wait_us` ではなく固定回数の空ループで作る。
- ④は 2 段階で進める。**第1段**：TC69 と同じ `analogReadPin()` のまま動かす（TC69 はこれで快調。確認されているのはこの形だけ）。**第2段**：無操作時のばらつきが合否基準（§9）を超えたら、`ADC->CS` を直接叩く形に替える（起動時に一度だけ入力を ADC2 に選び、④では START_ONCE を書いて READY を待つ）。第2段はビルド未確認。
- ADC は 12 bit で読み、**判定は 10 bit 単位のまま**（`>> 2`）。閾値を TC69 と比べられるようにするため。診断出力は 12 bit のまま出す。
- 1 走査の所要時間（推定）：`t_purge` 20 µs なら 52 交点で約 1.5 ms、6 µs なら約 0.8 ms。

### 6.3 判定

- 起動時校正（3 回捨てて 3 回合計）と 3 フレーム移動加算は TC69 のまま。
- 閾値の初期値は TC69 と同じ押下 +120（1 サンプルあたり、10 bit）。**既定の動作は TC69 の実挙動と同じ「閾値 1 本」**にする（`curr_matrix` を毎回ゼロから作る）。解放 +30 のヒステリシスを効かせる版はビルドオプションにし、打鍵感を比べて Sadao が選ぶ。
- ホームポジションの特例（TC69 は A キーだけ +220）は、キーごとの閾値表にして TS52K の座標で持つ。初期値は全キー同じ。
- QMK の `debounce()` は通さない（`CUSTOM_MATRIX = yes` のまま。lite にするなら `DEBOUNCE = 0`）。
- 起動時校正に、ベースラインが範囲外（10 bit で 5 未満、または 600 超）のキーを診断出力へ報告する処理を足す。範囲の数字は M1 の実測で見直す。
- bootmagic は使わない（起動直後の 2 フレームは押下を検出できない。firmware-audit.md §4.4-6）。ブートローダへは BOOTSEL ボタンか `QK_BOOT` で入る。

### 6.4 診断ビルド

実機立ち上げの前提。`CONSOLE_ENABLE = yes` で、次を出せるようにする（キーコードは出さなくてよい）。

1. 全交点の生値（12 bit）と校正値を 1 行 1 フレームで。
2. 指定した 1 交点だけを連続で（ばらつき測定用。1000 フレームの最小・最大・平均）。
3. `t_cap` と `t_purge` を実行中に変える手段（キー操作か raw HID）。
4. 走査 1 回の所要時間。

**このファームは TS52K の基板が届く前に TC69 の実機で動かせる**（表を 16 列 × 5 行、ピンを XIAO RP2040 のものにするだけ）。M1 をこのビルドで行えば、TC69 と TS52K を同じ物差しで比べられる。

## 8. 測定手順（実機が要るもの）

単位は断りがなければ 10 bit・1 サンプル。結果は `~/workspace/ts52k-ec/measurements/` に日付付きで残す。

### M1　TC69 実機の基準値（基板発注の前。Sadao の手作業）

目的：TS52K の合わせ先を実測にする。報告書 §7 の合否基準（全押下の差 300 以上など）をここで決め直す。

1. **今のファームを退避する。** TC69 を BOOTSEL で起動し、`picotool save -a tc69-backup.uf2`。これが無いと元の打鍵感に戻せない（QMK の最終版をビルドした成果物は残っていない。firmware-audit.md §5）。
2. 測定用ファームを書く。第一候補は §6.4 の診断ビルド（TC69 用の設定）。間に合わなければ `ref/tc69/firmware/sketch_tester/sketch_jan11a.ino` を arduino-pico でビルドする（ピン定義は RP2040 用が有効になっている。確認）。その場合、`loop()` の出力を生値に替える：`int v = adc_measured_val[j][i] - calibration_val[j][i] - adc_threshold; if(v<0) v=0;` をやめ、コメントアウトされている `int v = adc_measured_val[j][i];` を使う。元のままだと「校正値 +30」以下が全部 0 になり、ベースラインもばらつきも見えない。
3. 採る値（PC につないだまま、キーキャップ付き）：
   - **ベースライン**：無操作で 100 フレーム。全 69 キーの平均。
   - **無操作時のばらつき**：同じ 100 フレームの最大−最小。全キーの最悪値と、行ごと・列ごとの傾向。
   - **全押下**：各キーを底まで押して 20 フレームの平均。ベースラインとの差。最低でも各行 3 キー＋親指 2 キー＋ A キー。できれば全キー。
   - **漏れ込み**：1 キーを底まで押したまま、同じ列・隣の列・同じ行の別キー（押していない）の値の変化。3 か所以上。
   - **A キーに小指を載せた状態**の値（+220 の特例の根拠を数字にする）。
4. 余力があれば、パージの順序を `sense.ino` の順（読んでからパージ）に替えた版でも「漏れ込み」を採る。報告書の推定（TC69 で −6〜−18）が合うかを見る。合えば TS52K の −40〜−90 の推定も信用できる。
5. 測定後、`picotool load tc69-backup.uf2` で戻す。

オシロスコープがあれば追加で（プローブは ×10、GND は最短）：XIAO の ADC ピン（オペアンプ出力）の波形を、行の立ち上がりをトリガにして 1 枚。**ピークの時刻、ピークの高さ（無操作／全押下）、ADC が読んでいる時刻**（行が LOW に戻る直前の約 2 µs 前）が分かる。SENSE 節点には直接プローブを当てない（プローブの 10 pF 前後が節点を変える）。

### M2　試作基板の受け入れ（通電前後）

1. 通電前：`SENSE`–GND、`+3V3A`–GND、各 `COL`–GND の抵抗（COL は 100 kΩ、SENSE は開放、+3V3A は短絡なし）。
2. 通電後、プレートとばねを付ける前（電極だけ）：診断ビルドで全交点の生値。全部がほぼ同じ小さな値になるはず。0 に張り付く交点、突出する交点は配線不良。
3. 容量の実測（LCR メータがあれば、無通電、MUX 未実装の基板か MUX の入力パッドで）：列 1 本の対 GND 容量。**55〜60 pF の推定の検証**。大きく外れたら §7 を比例で直す。

### M3　取り込み時刻の決定

1. プレート・ばね・ドームを組んだ状態で、1 キーを底まで押したまま（重りで固定）、`t_cap` を 0〜10 µs の範囲で 0.5 µs 刻みに振り、差分（押下−ベースライン）を記録。
2. 差分が最大になる `t_cap` の少し後ろ（最大値の −2% 以内の範囲の中央）を採用値にする。
3. 4 隅と中央の計 5 キーで繰り返し、同じ値で全部が範囲に入ることを確かめる。
4. オシロがあれば TP_ADC の波形と突き合わせる。

### M4　パージ時間

`t_purge` を 20 → 10 → 6 → 4 µs と下げ、各段で M5 の漏れ込みを測る。漏れ込みが増え始める手前の 2 倍を採用値にする。急ぐ理由が無ければ 20 µs のままでよい。

### M5　漏れ込みと雑音（合否）

1. 無操作時のばらつき：全交点、1000 フレーム、USB でキー入力が流れている状態（別のキーボードで打ちながらではなく、診断出力そのものが USB 通信になる）。
2. 漏れ込み：最下段のキー（列容量が最大の列の末端）を押したまま、同じ列の行 1〜3、隣の列、同じ行を読む。c1、c7、c13 の 3 列で。
3. QSPI の影響：MX7 と MX8（島の真上）のばらつきを、ほかのキーと比べる。差があれば §6.2 の第2段（RAM 実行の徹底）へ進む。
4. エンコーダを回しながら MX64・MX74（エンコーダの隣）のばらつき。

### M6　感度の合わせ込み

M1 の TC69 の「全押下の差」と TS52K の値を比べる。TS52K が 1 割以上小さければ C2B は空のまま C2 を 270 pF へ、または R2 を 47 kΩ へ。大きければ C2B に 22〜47 pF を足す。ベースライン＋全押下が ADC 上限の 85% を超えないこと。

### M7　プレートの接地

R_PLATE を未実装（TC69 と同じ、浮き）と 0 Ω の両方で M5-1 を採り、ばらつきの小さい方を採用する。手をプレートに近づけたときのベースラインの動きも比べる。

### M8　温度と時間

起動直後と 30 分後のベースラインの差（全交点）。押下閾値の 1/4（30）を超えるキーがあれば、動作中の再校正（押されていないキーのベースラインをゆっくり追従させる）を検討する。TC69 は再校正なしで使えている。

## 10. 作業の順番

1. **M1（TC69 の基準値）**。診断ビルドを TC69 用に作るところから始めれば、ファームの主要部分も同時にできる。
2. KiCad 10 の復旧（`ensure-kicad.sh` が libpoppler の依存で失敗している）。
3. ts52k リポジトリに専用ブランチを切り、回路図（§2）→ 4層化とフットプリント置換 → 配置（§4）→ §5 の「配置の時点で止めて確かめること」→ 配線 → DRC（§5 のカスタムルール込み）。
4. プレートと固定穴（§4.2）の確定。ケースの高さの取り直し。ここは機構の作業で、本書の範囲外。
5. 発注（§1 のスタック指定）。
6. M2 → M3 → M5 → M6 → M4 → M7 → M8。

## 11. 残っている不確かさ

- 数値はすべてモデル推定で、実測はまだ一つも無い。最初の実測は M1。
- 2層が成立しないという判断（報告書 §3.2）は、幾何と TC69 の間隔規則から出したもので、基板上で配線して試してはいない。
- §4.1 の本数の数え上げは、提案した配置で数えただけで、配線はしていない。MUX B のまわり（リングの下に部品が入る）は実際に置いてみて詰まれば、(223, 103) から x 方向に数 mm 動かす。
- NiZ ハウジングと固定穴の干渉、プレートと基板の距離、ケースの高さは未検討。
- CD4051B の 3.3 V でのオン抵抗、RP2040 の ADC の取り込み時刻は公開情報で確定できなかった。どちらも M3 で吸収する。
- C2 の 300 pF と R2 の 43 kΩ は LCSC 品番を選んでいない。
- 4層と 2層の費用差は見ていない。
