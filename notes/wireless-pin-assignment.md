# 無線版GPIO割当て

2026-11-10更新。モジュール（U5）を基板左端へ移してアンテナを基板端・外向きにしたのに合わせ、マトリクス18本の割当てを組み直した（ブランチ claude-fable-antenna-2026-11-10）。回路図・PCBへ反映済み。ZMK側への反映はまだ行っていない。2026-11-07の旧割当ては表の右列に残す。

## 割当ての考え方

- モジュールは左端で、アンテナが西、電源・水晶のパッド列が東、パッド3〜14の列が北、パッド34〜55の列が南を向く。
- USBコネクタは北辺、電源・USBのパッド（28〜35）はモジュールの南東にある。北・東のパッドから出た線はUSBと電源の線を一度またぐ以外に東へ出られないので、信号はモジュールの外周順に、行き先のバスの並び順と同じ順で割り当てた。これでマトリクス18本は裏面だけでバスへ届く。
- 上段バスの入力6本（rpg1・rpg2・row1・row6・row2・row7）は北側のパッド4〜14。「standard drive, low frequency I/O only」の端子で、入力専用にする。
- 列6本は制限のない端子だけを使う。col6〜col2は東側のパッド16・20・22・24・26、col1は南側のパッド49。ZMKで `NRF_GPIO_DRIVE_H0H1` を明示する方針は変えない。
- 下段バスの行6本（row3・row8・row4・row9・row5・row10）は南側のパッド37・41・43・44・46・48。
- P0.15（パッド39、採用候補ブートローダーのLED出力）は引き続き未接続。NFC兼用のP0.09・P0.10も使わない。
- ダイオードの向き、`col2row`、行の内部プルダウン、エンコーダの内部プルアップは変えていない。

### この割当てで残る注記

- **col6（P0.27、パッド16）とcol5（P0.04、パッド20）はLF水晶の端子（パッド17・18）の隣**。配線は水晶から離れる向きへすぐ逃がしている。列は走査中だけ動く。Nordicの開発キットがP0.26・P0.27をI2Cに使っているという記憶はあるが、今回はネットワークが使えず出典を確認できていない。LF精度は試作で確認する項目に含める。
- **row3（P0.13、パッド37）はUSB D+（パッド35）の隣**。以前「37はUSBに隣接するので列には使わない」とした端子で、今回は入力（行）として使う。

## 予約端子・書き込み

| 用途 | GPIO／信号 | パッド |
| --- | --- | --- |
| LF水晶 | P0.00 / XL1、P0.01 / XL2 | 17、18 |
| リセット、SWDのnRESET | P0.18 | 40 |
| ブートローダーLED、基板は未接続 | P0.15 | 39 |
| SWDデータ、クロック | SWDIO、SWDCLK | 51、53 |
| SWDのVTref | nRF_VDD | 28のネットから分岐 |
| USBデータ | D−、D+ | 34、35 |

SWDIO・SWCLKはモジュール南側のパッドからB.CuだけでJ2へ届く。nRESET（パッド40は内側の列）はモジュール下のビアからF.Cuで外へ出し、SW1を経てJ2へ入る。VTrefはVDDコンデンサ列から分岐し、F.CuでJ2の手前まで渡す。経路は[配線記録](../pcb/placement-review/README.md)を参照。

## 電気条件・根拠

[Raytac Version K](https://cdn.sparkfun.com/assets/4/7/4/3/8/_nRF52840__MDBT50Q-1MV2___MDBT50Q-P1MV2_Ver.K_spec.pdf) §2.5–2.6を基準とする。パッド3〜14には「standard drive, low frequency I/O only」の制限があり、現在はそのうち4・6・8・10・12・14を入力に使う。列用16・20・22・24・26・49にはこの指定がない。

列の最大9接点同時押し負荷を考慮して高駆動を使う。標準駆動では絶対に動かないと判定したという意味ではない。内部プルダウン以外の抵抗は追加しない。

採用候補のAdafruit nRF52 Bootloader 0.11.0 / nice_nanoは[board.h](https://github.com/adafruit/Adafruit_nRF52_Bootloader/blob/c67f0bcf0fa8e841426335b1bbde91cda6ca1f50/src/boards/nice_nano/board.h)でP0.15をLEDに使う。別ブートローダーを使う場合は、そのピン使用を照合する。秋月の書き込み済みモジュールの詳細は未確認。SWD機材の選定は後日。

## ファームウェアへの引き継ぎ

- Windows側の変更対象・新旧対照・確認手順は[ZMK同期チェックリスト](zmk-pin-sync-checklist.md)を参照。このVMでは別リポジトリの編集・ビルドは行っていない。
- `col-gpios`、`row-gpios`をそれぞれcol1〜6、row1〜10の順に、上の表のGPIOで設定する。エンコーダはA=P1.11、B=P1.13。2026-11-10の表は回路図ネットリストとPCB（DRCの回路図照合）で一致を確認済み。旧表で作った設定があれば全18本を差し替える。
- 列の高駆動指定には[ZephyrのNordic GPIO定義](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/dt-bindings/gpio/nordic-nrf-gpio.h)を使う。
- QSPI等の周辺機能として使わず通常のGPIOとする。nice!nanoの外部電源制御も追加しない。
- エンコーダの回転方向は実機で設定順を確認する。
- 現在の検証UF2は以前の1×1最小構成。新しい18信号の割当て・高駆動設定・走査条件を反映したビルドや実機試験は未実施。
