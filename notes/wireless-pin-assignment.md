# 無線版GPIO割当て

2026-11-03。MDBT50Q-1MV2を使うTS52KのGPIO記録。既存のネット名とダイオードの向きを維持する。

## PCB仮配置で採用した変更方針

ユーザーと合意済み。USBを北へ向けた現在のモジュール配置に合わせ、南東から入る信号を南側のGPIOへ寄せる。

- ダイオードは反転しない。列6本をHigh出力、行10本を内部プルダウン入力とする`col2row`を維持する。
- **行入力10本とエンコーダA/B入力2本を、南側の物理パッド3〜14へ割り当てる。** これらは標準駆動・低周波I/O指定のある端子。入力として、端子に現れる走査信号も10 kHz以下となる構成で使う。
- **列出力6本は、現在の周波数制限指定のないGPIOを維持する。** 同じ列の最大9接点を押した負荷を考慮し、ZMK側で`NRF_GPIO_DRIVE_H0H1`を明示する。部品の追加はしない。
- 若い番号のGPIOを一律に除外する旧方針は撤回する。入力端子には列出力の合計負荷を駆動する役割がない。
- パッド3〜14の中でどの信号をどこへ結ぶかは、既存配線の並びと引き込み経路に合わせる。この時点では方針の記録と部品の仮配置を行い、回路図・PCBのGPIOネット変更およびZMK実装はまだ行っていない。

ZMKのGPIOマトリクスドライバとZephyrのNordic GPIOドライバは、Devicetreeに指定した駆動フラグを出力設定へ渡せる。実装時は[Zephyrの定義](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/dt-bindings/gpio/nordic-nrf-gpio.h)に従う。

## 現在ファイルに実装されている割当て（変更前）

以下は回路図・PCBへ転記済みの旧割当て。上記の採用方針に従って、行とエンコーダの入力先を今後更新する。新方針の最終接続表として使わない。

## 旧割当てを決めたときの根拠

- [Raytac Version K](https://cdn.sparkfun.com/assets/4/7/4/3/8/_nRF52840__MDBT50Q-1MV2___MDBT50Q-P1MV2_Ver.K_spec.pdf) §2.5、p17–18の端子表と照合した。18本とも§2.6の「standard drive, low frequency I/O only」の指定がないGPIOから選んだ。この指定のあるGPIOがキー入力に使えないという意味ではなく、今回は指定のない端子だけで足りる。
- LF水晶のP0.00/01、nRESETのP0.18、専用SWD端子を避ける。
- 採用候補のAdafruit nRF52 Bootloader 0.11.0 / nice_nanoは[board.h](https://github.com/adafruit/Adafruit_nRF52_Bootloader/blob/c67f0bcf0fa8e841426335b1bbde91cda6ca1f50/src/boards/nice_nano/board.h)でP0.15をLED出力にする。この端子をキーやエンコーダにつながない。
- 現在の最小構成のcol1=P0.06、row1=P0.08を維持する。GPIO1は現在のボード定義でも有効になっており、row2のみP1.08を使う。
- P0.13はTS52Kではrow6とする。nice!nanoの外部電源制御の設定をTS52Kへ追加しない。P0.07/11/12のトレース機能、P0.19/21/22/23のQSPI機能も有効にしない。通常のSWD書き込みは専用端子を使う。

周辺機能の予約はメーカー資料と採用候補ブートローダーに従い、マトリクスとエンコーダの信号割当てはTS52K用に決めた。

## キーとエンコーダの電気条件

キーのダイオードは既存どおりカソードが行側。ZMKの`col2row`で、列をアクティブHigh出力、行を内部プルダウン入力とする。各GPIOはVDDの電圧で動作する。行への外付けプルダウンは追加しない。

エンコーダA/Bは内部プルアップ入力とし、既存の外付け10 kΩ×2と100 nF×2は削除する。回転方向は実機確認時にA/Bの設定順で合わせられる。

## 予約端子と余り

| 用途 | GPIO／専用信号 | モジュールのパッド |
| --- | --- | --- |
| LF水晶 | P0.00 / XL1、P0.01 / XL2 | 17、18 |
| リセット、SWDのnRESET | P0.18 | 40 |
| ブートローダーLED出力、基板側は未接続 | P0.15 | 39 |
| SWDデータ、クロック | SWDIO、SWDCLK | 51、53 |
| SWDのVTref | VDD | 28 |
| USBデータ | D−、D+ | 34、35 |

旧割当てで周波数制限の指定がない未使用GPIOはP1.09（26）、P0.16（38）、P1.00（47）、P0.24（48）、P0.25（49）。NFCのP0.09/10も未接続。周波数制限指定のあるパッド3〜14は上記の新方針で入力へ使うため、未使用のまま固定する決定ではない。

## ファームウェアへの引き継ぎ

ファームウェア側では`col-gpios`をcol1〜col6、`row-gpios`をrow1〜row10の表の順に並べる。配列は0始まりなので、たとえば回路図のrow1は`RC(0, ...)`に対応する。物理キー配列に対するmatrix transformとエンコーダ設定はZMKの開発段階で実装する。

現在の検証UF2は1×1の最小構成で、18本全てをスキャンする設定ではない。旧接続表は無線版回路図とPCBへ反映し、[ネットリストで照合済み](../pcb/schematic-review/validation.json)。今回採用した入力端子の変更と列の高駆動設定は、まだ回路図・PCBのネットとファームウェアへ反映していない。

秋月の書き込み済みモジュールは搭載ブートローダーの詳細が未確認。上記のブートローダー競合確認はnice_nano 0.11.0に対するもの。別のブートローダーを使う場合はそのピン使用を照合し、必要なら必須のSWDランドから確認済みのブートローダーを書き込む。
